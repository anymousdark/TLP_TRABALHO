Estrutura completa do projecto Lakastech — Loja Virtual Angolana

Visao Geral

O Lakastech e um sistema de loja virtual desenvolvido em PHP puro com MySQL. O projecto segue uma arquitectura monolítica simples: cada pagina PHP renderiza HTML no servidor com CSS glassmorphism (macOS style) e JavaScript para interaccao (tema dark, animacoes, preview de imagens).

PHP 8.x MySQL 8.x CSS3 Glassmorphism JavaScript Vanilla XAMPP VS Code

Principais Caracteristicas

  • CRUD de produtos com upload de imagem e estoque inline
  • Checkout em 3 etapas com transacao segura (begin_transaction / rollback)
  • Metodos de pagamento angolanos: Multicaixa Express, BFA Net, BAI Directo
  • Perfil de utilizador com abas e gestao de dados de pagamento pessoais
  • Painel admin completo: produtos, pedidos, utilizadores, metodos de pagamento
  • Seis animais africanos animados em SVG com CSS keyframes
  • Tema dark/light persistente com localStorage
  • Design responsivo com glass effect (backdrop-filter: blur + saturate)

Banco de Dados

O sistema usa 5 tabelas no MySQL:

TabelaColunasDescricao
usuarios id, nome, email, senha, tipo, criado_em, pagamento_info Utilizadores (cliente/admin) com dados de pagamento pessoais em JSON
produtos id, nome, descricao, preco, estoque, categoria, imagem, criado_em Produtos da loja com categoria e imagem local
pedidos id, usuario_id, total, endereco, telefone, metodo_pagamento, status, data_pedido Pedidos com endereco de entrega e metodo de pagamento escolhido
itens_pedido id, pedido_id, produto_id, quantidade, preco_unitario Itens de cada pedido (FK para pedidos ON DELETE CASCADE)
metodos_pagamento id, nome, descricao, conta, titular, ativo, criado_em Metodos de pagamento da loja (gerivel pelo admin)

Relacionamentos

-- usuarios 1---N pedidos
FOREIGN KEY (usuario_id) REFERENCES usuarios(id)

-- pedidos 1---N itens_pedido
FOREIGN KEY (pedido_id) REFERENCES pedidos(id) ON DELETE CASCADE

-- itens_pedido N---1 produtos
FOREIGN KEY (produto_id) REFERENCES produtos(id)

Fluxos do Sistema

Checkout (3 etapas)

Carrinho → Dados → Revisar → Confirmado
  1. Carrinho — Utilizador ve os itens e clica "Finalizar Compra"
  2. Dados — Escolhe o metodo de pagamento e preenche endereco (rua, bairro, municipio, telefone)
  3. Revisar — Confere todos os dados antes de confirmar
  4. Confirmado — Transacao com begin_transaction(): cria pedido, insere itens, reduz estoque. Exibe dados bancarios para transferencia.

Admin — Gestao de Produtos

Formulario → Salvar → Lista

O admin preenche o formulario no sidebar, faz upload de imagem (com preview), define categoria (com autocomplete).
A lista de produtos permite edicao inline do estoque, ordenacao por coluna, e busca por nome/descricao.

Admin — Gestao de Pedidos

Filtro → Cards → Status

Stats clicaveis filtram por status (todos, pendentes, pagos, cancelados).
Cada pedido e um card com dados do cliente, pagamento, endereco, itens e formulario para alterar o status.

Output Buffering

Para evitar erros "headers already sent", o sistema usa output buffering:

  • header.php chama ob_start() no inicio
  • footer.php chama ob_end_flush() no fim
  • Isto permite chamar header() / setcookie() apos incluir header.php

Theme Toggle — Modo Claro / Escuro

Botao ☾ no canto direito da navbar que alterna entre tema claro (light glass) e escuro (dark glass).

Funcionamento

  1. CSS: O tema escuro e definido pela classe .dark-theme no body, que sobrepoe as variaveis CSS --bg, --card, --text, --border para tons escuros.
  2. JavaScript: O botao no footer.php escuta click, alterna a classe no body e salva a preferencia em localStorage com chave theme.
  3. Persistencia: Um script inline no header.php le localStorage.getItem('theme') antes do HTML renderizar e aplica a classe imediatamente, evitando flash de tema incorrecto.
  4. Icone: O botao mostra fa-moon (lua) no tema claro e fa-sun (sol) no tema escuro, alternando via JS.

Estrutura do JS (footer.php)

document.getElementById('theme-toggle').addEventListener('click', function() {
    document.body.classList.toggle('dark-theme');
    const theme = document.body.classList.contains('dark-theme') ? 'dark' : 'light';
    localStorage.setItem('theme', theme);
    this.querySelector('i').className = theme === 'dark'
        ? 'fas fa-sun'
        : 'fas fa-moon';
});

// Aplicar tema salvo antes do render (header.php)
if (localStorage.getItem('theme') === 'dark') {
    document.body.classList.add('dark-theme');
}

Decisoes Tecnicas

  • Pagamento info como JSON — O campo pagamento_info em usuarios e JSON para simplicidade, sem tabela extra.
  • Output buffering — ob_start() em header.php permite redirects apos incluir o header.
  • FK constraint em itens_pedido — Ao eliminar um produto, primeiro apaga os registos em itens_pedido para evitar violacao de FK.
  • Checkout transacional — begin_transaction() + commit() / rollback() garante integridade dos pedidos.
  • Metodos de pagamento via DB — As contas bancarias da loja sao geriveis pelo admin em admin_pagamento.php, eliminando codigo hardcoded.
  • FOR UPDATE — No checkout, usa SELECT ... FOR UPDATE para travar o registo do produto e evitar condicoes de corrida no estoque.
